# VibeSprint submission checklist

Use this during final review. Copy the required information into the project README and the selected documentation card. Mark an item complete only after the app or artifact exists.

- [ ] **Runnable app:** Working preview URL or self-contained project folder. Verify the exact run steps from a fresh start with sample data and no secrets or private service.
- [ ] **README.md:** Project name, one-sentence problem statement, 3–5 features that actually work (including the twist), exact preview/run steps, a three-step judge demo using sample data, known limitations, and links to the two screenshots.
- [ ] **Selected documentation card:** Complete the one drawn at the event (5–8 minute timebox). Use the card guide below.
- [ ] **Two screenshots:** One of the main flow and one of the actual result or confirmation.
- [ ] **Recording:** Optional 30–60 second backup when the preview works; required if there is no working preview. Show the main action and its result.
- [ ] **AI-use note:** Name the AI tools used and one specific thing the team fixed or changed.

## Documentation card guide

| Card | What to include |
| --- | --- |
| DOC-01 · README & Quickstart | Purpose, features, no-secret setup, demo data, screenshots, and known limitations. A judge should know what to click within 30 seconds. |
| DOC-02 · Judge Runbook | Numbered 60-second demo: starting state, exact actions, expected output, where the twist appears, and which features are simulated. |
| DOC-03 · Five-Test Checklist | Steps and expected results for invalid input, the happy path, the twist, reset or refresh, and a boundary case. |
| DOC-04 · User Quickstart | Four steps for a first-time user: what the app does, what to enter, what result to expect, and how to recover from a mistake. |
| DOC-05 · Data & Privacy Note | Stored fields, any browser storage used, what is fictional, what never leaves the browser, and confirmation that no real secrets are included. |
| DOC-06 · Handoff & Limitations | Key files and components, location of core logic, how demo data resets, what is mocked, and the top three improvements for a real deployment. |
